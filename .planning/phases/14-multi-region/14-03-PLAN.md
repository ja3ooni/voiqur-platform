# Plan 14-03: Data Residency Enforcement

**Phase:** 14 · multi-region
**Requirement:** MULTI-04
**Complexity:** High
**Depends on:** 14-01, 14-02

## Objective

Add four layers of data residency enforcement on top of the regional overlays: (a) egress NetworkPolicies scoped to regional CIDR blocks to block cross-region traffic at L4; (b) an OPA/Gatekeeper admission constraint that rejects Deployments lacking the correct region/residency labels; (c) a `RegionPolicy` Pydantic model in `APIConfig` with hard guardrails that cannot be flipped from admin settings; (d) `EdgeOrchestrator` integration that enforces `RegionPolicy.allowed_source_countries` at routing time. These four mechanisms together implement decisions D-02, D-07, D-08, D-09, D-15, D-16, and D-17.

### 3. OPA/Gatekeeper ConstraintTemplate

**Decision (resolving RESEARCH open question 4):** Use **Gatekeeper** — it is CNCF-graduated with the widest production adoption and the YAML constraint format integrates cleanly with Kustomize.

Create a shared constraint template (lives in `kiro/voiquyr/k8s/overlays/base/gatekeeper-data-residency-template.yaml`):

```yaml
apiVersion: templates.gatekeeper.sh/v1
kind: ConstraintTemplate
metadata:
  name: voiquyrdataresidency
spec:
  crd:
    spec:
      names: { kind: VoiquyrDataResidency }
      validation:
        openAPIV3Schema:
          type: object
          properties:
            requiredRegion: { type: string }
            requiredDataResidency: { type: string }
            requiredNodeLabel: { type: string }
  targets:
    - target: admission.k8s.gatekeeper.sh
      rego: |
        package voiquyrdataresidency
        violation[{"msg": msg}] {
          input.review.kind.kind == "Deployment"
          input.review.object.metadata.namespace == "voiquyr"
          env := input.review.object.spec.template.spec.containers[_].env
          not has_env(env, "DATA_RESIDENCY", input.parameters.requiredDataResidency)
          msg := sprintf("Deployment missing DATA_RESIDENCY=%v env var", [input.parameters.requiredDataResidency])
        }
        violation[{"msg": msg}] {
          input.review.kind.kind == "Deployment"
          input.review.object.metadata.namespace == "voiquyr"
          affinity := input.review.object.spec.template.spec.affinity.nodeAffinity.requiredDuringSchedulingIgnoredDuringExecution.nodeSelectorTerms[_]
          not has_label_match(affinity, input.parameters.requiredNodeLabel)
          msg := sprintf("Deployment missing node affinity for label %v", [input.parameters.requiredNodeLabel])
        }
        has_env(envs, name, value) {
          envs[_].name == name
          envs[_].value == value
        }
        has_label_match(term, label) {
          term.matchExpressions[_].key == label
        }
```

Add it to `kiro/voiquyr/k8s/overlays/base/kustomization.yaml` under `resources:`.

### 5. Extend APIConfig with RegionPolicy

Edit `kiro/voiquyr/k8s/../kiro/voiquyr/src/api/config.py` (actual path: `kiro/voiquyr/src/api/config.py`).

Add a new `RegionPolicy` Pydantic model per RESEARCH §6:

```python
import json
import os
from typing import List
from pydantic import BaseModel, Field, validator


class RegionPolicy(BaseModel):
    """Per-region routing and residency enforcement policy.

    Hard guardrail fields (deny_cross_region_*) cannot be set to False by
    admin actions — they are validated at startup and remain immutable for
    the process lifetime.
    """

    region_id: str = Field(
        default_factory=lambda: os.getenv("REGION_ID", "frankfurt")
    )
    jurisdiction: str = Field(
        default_factory=lambda: os.getenv("DATA_RESIDENCY", "eu")
    )
    allowed_source_countries: List[str] = Field(
        default_factory=lambda: json.loads(
            os.getenv(
                "ALLOWED_SOURCE_COUNTRIES",
                '["DE","FR","NL","BE","AT","PL","SE","DK","FI","IE","PT","GR","CZ","RO","HU","IT","ES"]',
            )
        )
    )
    deny_cross_region_audio: bool = True
    deny_cross_region_transcripts: bool = True
    deny_cross_region_prompts: bool = True
    max_metadata_retention_days: int = Field(
        default_factory=lambda: int(os.getenv("MAX_METADATA_RETENTION_DAYS", "30"))
    )
    compliance_framework: str = Field(
        default_factory=lambda: os.getenv("COMPLIANCE_FRAMEWORK", "gdpr")
    )
    erasure_sla_days: int = Field(
        default_factory=lambda: int(os.getenv("ERASURE_SLA_DAYS", "30"))
    )

    @validator("deny_cross_region_audio", "deny_cross_region_transcripts",
               "deny_cross_region_prompts", allow_reuse=True)
    def hard_guardrails_must_stay_true(cls, value: bool) -> bool:
        if value is False:
            raise ValueError(
                "deny_cross_region_* guardrails cannot be False — "
                "this is a compile-time invariant per D-09/D-16."
            )
        return value

    @validator("jurisdiction")
    def jurisdiction_must_be_known(cls, value: str) -> str:
        allowed = {"eu", "uae", "uae-pdpl", "uk", "ch", "me", "asia"}
        if value not in allowed:
            raise ValueError(f"Unknown jurisdiction: {value}")
        return value
```

Add `region_policy: RegionPolicy = Field(default_factory=RegionPolicy)` to `APIConfig`.

### 6. Integrate RegionPolicy into EdgeOrchestrator

Edit `kiro/voiquyr/src/core/edge_orchestrator.py`.

Add a `RegionPolicy`-aware constructor variant and a country-allowlist check in `route_call`:

```python
def __init__(self, region_policy: Optional["RegionPolicy"] = None):
    self.endpoints: Dict[Jurisdiction, List[RegionalEndpoint]] = {}
    self.routing_rules: Dict[str, RoutingRule] = {}
    self.region_policy = region_policy
    self._initialize_default_rules()

async def route_call(self, context: CallContext) -> Optional[RegionalEndpoint]:
    # Hard sovereignty gate — runs before any routing rule lookup.
    if self.region_policy is not None:
        if context.source_country not in self.region_policy.allowed_source_countries:
            logger.warning(
                "Rejecting call %s: source_country=%s not in regional allowlist=%s",
                context.call_id, context.source_country,
                self.region_policy.allowed_source_countries,
            )
            return None
    # ... existing logic ...
```

### 8. Startup invariant assertion

def _assert_residency_invariants(policy: RegionPolicy) -> None:

## Notes

- Decision D-09/D-16: hard guardrails (`deny_cross_region_*`) MUST NOT be flippable at runtime. The Pydantic validator + startup assertion enforce this in two independent layers.
- Decision D-07: rejecting calls (returning `None`) is the correct sovereignty behaviour — never silently reroute cross-region. This is the EdgeOrchestrator contract.
- The AWS CIDR lists in the NetworkPolicies are samples — implementation must pull current ranges from `https://ip-ranges.amazonaws.com/ip-ranges.json` filtered by region. A small `scripts/refresh-aws-cidrs.sh` helper is recommended but out of scope for this plan.
- Gatekeeper itself is not installed by this overlay — production must install the Gatekeeper operator separately (`gatekeeper-system` namespace). The overlays only ship the ConstraintTemplate and Constraint CRs that Gatekeeper consumes.
- Resolves RESEARCH open question 4 (Gatekeeper over Kyverno) and open question 2 (region-specific `eu-node`/`uae-node` labels for auditability).
- The Pydantic validator approach assumes Pydantic v1 syntax (`@validator`). If the codebase has migrated to v2, use `@field_validator` instead — check `requirements.txt` before implementing.
- The Admin endpoint is intentionally read-only in this plan. Plan 14-04 covers cross-region policy distribution (signed pushes from a global control plane).
