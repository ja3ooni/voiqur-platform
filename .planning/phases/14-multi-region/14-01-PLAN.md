# Plan 14-01: Frankfurt Kustomize Overlay

**Phase:** 14 · multi-region
**Requirement:** MULTI-01
**Complexity:** Medium
**Depends on:** None

## Objective

Create the Kustomize overlay structure (`base` + `frankfurt`) that renders the existing Helm chart into a deployable Frankfurt manifest set with ExternalDNS Route53 geolocation annotations, EU compliance labels, EU node affinity, and a region-local ExternalDNS controller. This establishes the repeatable overlay pattern that Plan 14-02 (UAE) and future sovereign regions will mirror.

## Tasks

### 1. Generalise the node affinity helper

The `_helpers.tpl` currently hardcodes `compliance.euvoice.ai/eu-node: "true"` in the `euvoice-platform.affinity` block (per RESEARCH §3 "One gap"). This prevents the UAE overlay from selecting `uae-node` without patching every Deployment.

- Edit `kiro/voiquyr/k8s/helm/euvoice-platform/templates/_helpers.tpl`:
  - Replace the hardcoded `compliance.euvoice.ai/eu-node` label key with `{{ .Values.global.nodeComplianceLabel | default "compliance.euvoice.ai/eu-node" }}`.
  - Keep `topology.kubernetes.io/region` driven by `.Values.global.region`.
- Add `nodeComplianceLabel: "compliance.euvoice.ai/eu-node"` to the `global:` block in `kiro/voiquyr/k8s/helm/euvoice-platform/values.yaml` so the Frankfurt default remains unchanged.

**Test (TDD):**
- Write test (`tests/test_helm_affinity.py`): run `helm template kiro/voiquyr/k8s/helm/euvoice-platform` and assert the rendered API Deployment still requires `compliance.euvoice.ai/eu-node = "true"` and `topology.kubernetes.io/region = eu-central-1`.
- Expected: rendered manifest unchanged from current behaviour for the default values; the values key exists and overrides cleanly when set.

### 2. Create the Kustomize base

- Create directory `kiro/voiquyr/k8s/overlays/base/`.
- Create `kiro/voiquyr/k8s/overlays/base/kustomization.yaml` using the Kustomize `helmCharts` generator (kustomize v4.1+) pointing at the local Helm chart:
  ```yaml
  apiVersion: kustomize.config.k8s.io/v1beta1
  kind: Kustomization
  helmCharts:
    - name: euvoice-platform
      releaseName: euvoice
      namespace: voiquyr
      version: 0.1.0
      path: ../../helm/euvoice-platform
      valuesFile: ../../helm/euvoice-platform/values.yaml
  ```
- Add a top-level `kiro/voiquyr/k8s/overlays/README.md` (short — one screen) explaining the layout and the `kustomize build --enable-helm` command developers must use.

**Test (TDD):**
- Write test (`tests/test_overlay_base.py`): shell out to `kustomize build --enable-helm kiro/voiquyr/k8s/overlays/base/` and assert exit code 0 and that the output contains a `kind: Deployment` for the `euvoice-api`.
- Expected: base renders without error.

### 3. Create the Frankfurt overlay directory and values

- Create directory `kiro/voiquyr/k8s/overlays/frankfurt/`.
- Create `kiro/voiquyr/k8s/overlays/frankfurt/values-frankfurt.yaml` with the Frankfurt-specific values (see RESEARCH §3 matrix):
  ```yaml
  global:
    region: "eu-central-1"
    dataResidency: "eu"
    gdprCompliance: true
    aiActCompliance: true
    storageClass: "gp3-encrypted"
    nodeComplianceLabel: "compliance.euvoice.ai/eu-node"
  namespace:
    name: "voiquyr"
    labels:
      compliance: "gdpr"
      region: "eu"
      "pod-security.kubernetes.io/enforce": "restricted"
    annotations:
      "compliance.euvoice.ai/gdpr": "enabled"
      "compliance.euvoice.ai/ai-act": "enabled"
      "compliance.euvoice.ai/region": "frankfurt"
  ingress:
    hosts:
      - host: api.voiquyr.eu
        paths:
          - { path: /, pathType: Prefix, service: api }
      - host: app.voiquyr.eu
        paths:
          - { path: /, pathType: Prefix, service: dashboard }
      - host: command.voiquyr.eu
        paths:
          - { path: /api, pathType: Prefix, service: commandCenterApi }
          - { path: /, pathType: Prefix, service: commandCenterUi }
    tls:
      - secretName: voiquyr-tls-eu
        hosts: [api.voiquyr.eu, app.voiquyr.eu, command.voiquyr.eu]
  monitoring:
    alertmanager:
      channel: "#voiquyr-alerts-eu"
  api:
    env:
      REGION_ID: "frankfurt"
      DATA_RESIDENCY: "eu"
  ```

### 4. Create the Frankfurt ingress patch (ExternalDNS Route53 geolocation)

Create `kiro/voiquyr/k8s/overlays/frankfurt/ingress-patch.yaml` as a strategic-merge patch that adds ExternalDNS Route53 geolocation annotations to the rendered Ingress (per RESEARCH §2):

```yaml
apiVersion: networking.k8s.io/v1
kind: Ingress
metadata:
  name: euvoice-euvoice-platform
  annotations:
    external-dns.alpha.kubernetes.io/hostname: "api.voiquyr.eu,app.voiquyr.eu,command.voiquyr.eu"
    external-dns.alpha.kubernetes.io/aws-geolocation-continent-code: "EU"
    external-dns.alpha.kubernetes.io/aws-set-identifier: "frankfurt"
    external-dns.alpha.kubernetes.io/aws-weight: "100"
    external-dns.alpha.kubernetes.io/ttl: "60"
```

Confirm the rendered Ingress name by running `helm template` first — adjust `metadata.name` to match exactly.

### 5. Create the Frankfurt namespace patch

Create `kiro/voiquyr/k8s/overlays/frankfurt/namespace-patch.yaml` for compliance labels not coverable by values alone (e.g., Pod Security Admission):

```yaml
apiVersion: v1
kind: Namespace
metadata:
  name: voiquyr
  labels:
    pod-security.kubernetes.io/enforce: restricted
    pod-security.kubernetes.io/audit: restricted
    pod-security.kubernetes.io/warn: restricted
    compliance.euvoice.ai/region: frankfurt
    compliance.euvoice.ai/jurisdiction: eu
```

### 6. Create the Frankfurt ExternalDNS deployment

Create `kiro/voiquyr/k8s/overlays/frankfurt/externaldns-deployment.yaml` containing:
- `Namespace external-dns` (with the same PSA labels)
- `ServiceAccount external-dns`
- `ClusterRole external-dns` (verbs: get/watch/list on services, endpoints, pods, ingresses, nodes)
- `ClusterRoleBinding external-dns`
- `Deployment external-dns` scoped to EU per RESEARCH §2:
  ```yaml
  containers:
    - name: external-dns
      image: registry.k8s.io/external-dns/external-dns:v0.14.2
      args:
        - --source=ingress
        - --source=service
        - --domain-filter=voiquyr.eu
        - --provider=aws
        - --aws-zone-type=public
        - --aws-region=eu-central-1
        - --registry=txt
        - --txt-owner-id=voiquyr-frankfurt
        - --txt-prefix=frankfurt-
        - --policy=sync
  ```

The deployment is added as a `resources:` entry in `kustomization.yaml` (not a patch).

### 7. Wire up the Frankfurt `kustomization.yaml`

Create `kiro/voiquyr/k8s/overlays/frankfurt/kustomization.yaml`:

```yaml
apiVersion: kustomize.config.k8s.io/v1beta1
kind: Kustomization
namespace: voiquyr
resources:
  - ../base
  - externaldns-deployment.yaml
patches:
  - path: ingress-patch.yaml
    target:
      kind: Ingress
  - path: namespace-patch.yaml
    target:
      kind: Namespace
      name: voiquyr
helmCharts:
  - name: euvoice-platform
    releaseName: euvoice
    namespace: voiquyr
    path: ../../helm/euvoice-platform
    valuesFile: values-frankfurt.yaml
```

- Tests must run from `kiro/voiquyr/` (the pytest root). Use absolute paths or `pytest.fixture` to resolve repo paths.
