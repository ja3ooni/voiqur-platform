# Plan 14-02: UAE Kustomize Overlay

**Phase:** 14 · multi-region
**Requirement:** MULTI-02
**Complexity:** Medium
**Depends on:** 14-01

## Objective

Create the `k8s/overlays/uae/` Kustomize overlay mirroring the Frankfurt structure with UAE-specific values (`me-central-1`, UAE PDPL compliance labels, `voiquyr.ae` hostnames, UAE KMS-backed StorageClass, UAE-scoped ExternalDNS). The two overlays must be structurally identical to prove the sovereign-region template is repeatable for future jurisdictions per D-05.

## Tasks

### 1. Create the UAE values file

Create `kiro/voiquyr/k8s/overlays/uae/values-uae.yaml` mirroring `values-frankfurt.yaml` with UAE substitutions per RESEARCH §3 matrix:

```yaml
global:
  region: "me-central-1"
  dataResidency: "uae"
  gdprCompliance: false
  aiActCompliance: false
  storageClass: "gp3-encrypted-uae"
  nodeComplianceLabel: "compliance.euvoice.ai/uae-node"
namespace:
  name: "voiquyr"
  labels:
    compliance: "uae-pdpl"
    region: "uae"
  annotations:
    "compliance.euvoice.ai/uae-pdpl": "enabled"
    "compliance.euvoice.ai/region": "uae"
ingress:
  hosts:
    - host: api.voiquyr.ae
      paths:
        - { path: /, pathType: Prefix, service: api }
    - host: app.voiquyr.ae
      paths:
        - { path: /, pathType: Prefix, service: dashboard }
    - host: command.voiquyr.ae
      paths:
        - { path: /api, pathType: Prefix, service: commandCenterApi }
        - { path: /, pathType: Prefix, service: commandCenterUi }
  tls:
    - secretName: voiquyr-tls-uae
      hosts: [api.voiquyr.ae, app.voiquyr.ae, command.voiquyr.ae]
monitoring:
  alertmanager:
    channel: "#voiquyr-alerts-uae"
api:
  env:
    REGION_ID: "uae"
    DATA_RESIDENCY: "uae"
```

**Decision (resolving RESEARCH open question 1):** UAE region is AWS `me-central-1` (UAE) — the codebase's AWS-first signals (NLB annotations, KMS) make AWS the lower-friction choice. UAE PDPL is satisfied by `me-central-1` regional residency. If sovereign cloud later becomes a hard constraint, the StorageClass and ExternalDNS args are the only files that change.

### 2. Create the UAE StorageClass

The Frankfurt chart relies on the cluster-provided `gp3-encrypted` StorageClass. UAE needs a parallel `gp3-encrypted-uae` StorageClass referencing the UAE KMS key. Create `kiro/voiquyr/k8s/overlays/uae/storageclass-uae.yaml`:

```yaml
apiVersion: storage.k8s.io/v1
kind: StorageClass
metadata:
  name: gp3-encrypted-uae
provisioner: ebs.csi.aws.com
parameters:
  type: gp3
  encrypted: "true"
  kmsKeyId: "arn:aws:kms:me-central-1:ACCOUNT_PLACEHOLDER:key/UAE_KEY_PLACEHOLDER"
  fsType: ext4
volumeBindingMode: WaitForFirstConsumer
reclaimPolicy: Retain
allowVolumeExpansion: true
```

Document in the overlay README that `ACCOUNT_PLACEHOLDER` and `UAE_KEY_PLACEHOLDER` must be substituted at deploy time via `kustomize edit set` or environment-specific kustomization layering — never committed.

### 3. Create the UAE ingress patch

Create `kiro/voiquyr/k8s/overlays/uae/ingress-patch.yaml` mirroring the Frankfurt patch with UAE Route53 geolocation annotations:

```yaml
apiVersion: networking.k8s.io/v1
kind: Ingress
metadata:
  name: euvoice-euvoice-platform
  annotations:
    external-dns.alpha.kubernetes.io/hostname: "api.voiquyr.ae,app.voiquyr.ae,command.voiquyr.ae"
    external-dns.alpha.kubernetes.io/aws-geolocation-country-code: "AE"
    external-dns.alpha.kubernetes.io/aws-set-identifier: "uae"
    external-dns.alpha.kubernetes.io/aws-weight: "100"
    external-dns.alpha.kubernetes.io/ttl: "60"
```

Per RESEARCH §2, `country-code: AE` is used for UAE specifically — GCC neighbour mapping is deferred to Plan 14-04 (DNS geo-routing completion).

### 4. Create the UAE namespace patch

Create `kiro/voiquyr/k8s/overlays/uae/namespace-patch.yaml`:

```yaml
apiVersion: v1
kind: Namespace
metadata:
  name: voiquyr
  labels:
    pod-security.kubernetes.io/enforce: restricted
    pod-security.kubernetes.io/audit: restricted
    pod-security.kubernetes.io/warn: restricted
    compliance.euvoice.ai/region: uae
    compliance.euvoice.ai/jurisdiction: uae-pdpl
```

### 5. Create the UAE ExternalDNS deployment

Create `kiro/voiquyr/k8s/overlays/uae/externaldns-deployment.yaml`. Structurally identical to the Frankfurt manifest but UAE-scoped per RESEARCH §2:

```yaml
# Same Namespace/ServiceAccount/ClusterRole/ClusterRoleBinding shape as Frankfurt.
# Deployment args:
- --source=ingress
- --source=service
- --domain-filter=voiquyr.ae
- --provider=aws
- --aws-zone-type=public
- --aws-region=me-central-1
- --registry=txt
- --txt-owner-id=voiquyr-uae
- --txt-prefix=uae-
- --policy=sync
```

The `txt-owner-id` and `txt-prefix` differ from Frankfurt — this is the cross-region isolation guarantee from RESEARCH §2.

### 6. Wire up the UAE `kustomization.yaml`

Create `kiro/voiquyr/k8s/overlays/uae/kustomization.yaml` mirroring Frankfurt:

```yaml
apiVersion: kustomize.config.k8s.io/v1beta1
kind: Kustomization
namespace: voiquyr
resources:
  - ../base
  - storageclass-uae.yaml
  - externaldns-deployment.yaml
patches:
  - path: ingress-patch.yaml
    target: { kind: Ingress }
  - path: namespace-patch.yaml
    target: { kind: Namespace, name: voiquyr }
helmCharts:
  - name: euvoice-platform
    releaseName: euvoice
    namespace: voiquyr
    path: ../../helm/euvoice-platform
    valuesFile: values-uae.yaml
```

## Notes

- Decision D-05/D-06: UAE must be fully sovereign — no fallback to Frankfurt. This is enforced at the routing layer (Plan 14-03) and the data residency layer (also 14-03). This plan only delivers the deployable manifests.
- Decision D-12: structural parity is non-negotiable — if Frankfurt has a file, UAE has the equivalent file. Anyone reviewing the diff between `overlays/frankfurt/` and `overlays/uae/` should see only values, not new files (except the StorageClass which is structural to UAE because the EU side uses an out-of-chart cluster default).
- The KMS ARN is a placeholder — production deployment will substitute via `kustomize edit set` or a sealed-secret-style overlay layer.  Do NOT commit a real KMS key ARN.
- `cloudflare-proxied` fallback (RESEARCH §2) is out of scope here — both overlays use AWS Route53. If a second DNS provider is needed, add it as a separate ExternalDNS deployment per region in a future plan.
- UAE PDPL erasure SLA is 30 days (same as GDPR per CLAUDE.md compliance matrix). The existing `security.auditLogging.retention: 7y` value remains compatible.
- The test for "no cross-region leakage" is the strongest guarantee that the overlays are independent. It must run as part of every CI build.
