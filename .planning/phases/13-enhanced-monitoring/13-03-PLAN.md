# Plan 13-03: Helm Monitoring Manifests

## Objective

Add all Kubernetes monitoring infrastructure to the Helm chart as a single new template file `monitoring.yaml`:
- ServiceMonitor CRD (kube-prometheus-stack) for Prometheus scrape discovery
- PrometheusRule with 4 alert rules
- Alertmanager configuration pointing to Slack webhook
- Two pre-provisioned Grafana dashboard ConfigMaps

## Tasks

### Task 1: Add monitoring values to values.yaml

<read_first>
- `kiro/voiquyr/k8s/helm/euvoice-platform/values.yaml` — existing values structure; add a new `monitoring:` top-level section at the end, following the existing formatting conventions
- `.planning/phases/13-enhanced-monitoring/13-CONTEXT.md` — D-08: Alertmanager Slack webhook via Helm values (never hardcoded); D-09: four alert rules; D-12: ServiceMonitor CRD
</read_first>

<action>
Add the following section to the end of `kiro/voiquyr/k8s/helm/euvoice-platform/values.yaml`:

```
monitoring:
  enabled: true

  serviceMonitor:
    interval: "30s"
    scrapeTimeout: "10s"
    # Must match the label selector on the API service
    selector:
      matchLabels:
        app.kubernetes.io/component: api

  alertmanager:
    # Set to your Slack webhook URL via --set or a sealed secret
    slackWebhookUrl: ""
    channel: "#voiquyr-alerts"
    # groupWait and groupInterval for Alertmanager
    groupWait: "30s"
    groupInterval: "5m"
    repeatInterval: "1h"

  grafana:
    sidecar:
      dashboards:
        enabled: true
        label: grafana_dashboard
        labelValue: "1"
```
</action>

</acceptance_criteria>

### Task 2: Create monitoring.yaml template

</read_first>

<action>
Create `kiro/voiquyr/k8s/helm/euvoice-platform/templates/monitoring.yaml` with the following sections, each guarded by `{{- if .Values.monitoring.enabled }}`:

**Section 1 — ServiceMonitor CRD:**
```yaml
apiVersion: monitoring.coreos.com/v1
kind: ServiceMonitor
metadata:
  name: {{ include "euvoice-platform.fullname" . }}-api
  namespace: {{ .Values.namespace.name }}
  labels:
    {{- include "euvoice-platform.labels" . | nindent 4 }}
    app.kubernetes.io/component: monitoring
spec:
  selector:
    matchLabels:
      app.kubernetes.io/component: api
  endpoints:
    - port: http
      path: /metrics
      interval: {{ .Values.monitoring.serviceMonitor.interval }}
      scrapeTimeout: {{ .Values.monitoring.serviceMonitor.scrapeTimeout }}
```

**Section 2 — PrometheusRule with 4 alert rules:**

Alert 1 — VoiquyrLatencyWarning (WARNING, 2m):
```
expr: histogram_quantile(0.95, sum(rate(voiquyr_call_latency_ms_bucket[5m])) by (le)) > 500
```

Alert 2 — VoiquyrLatencyCritical (CRITICAL, 1m):
```
expr: histogram_quantile(0.95, sum(rate(voiquyr_call_latency_ms_bucket[5m])) by (le)) > 800
```

Alert 3 — VoiquyrCircuitBreakerOpen (CRITICAL, immediately):
```
expr: voiquyr_circuit_breaker_state == 1
```

Alert 4 — VoiquyrHighErrorRate (WARNING, 5m):
```
expr: sum(rate(voiquyr_stt_latency_ms_count{status="error"}[5m])) / sum(rate(voiquyr_stt_latency_ms_count[5m])) > 0.05
```

Each alert must have labels: `severity` and `team: voiquyr`, plus an `annotations.summary` and `annotations.description`.

**Section 3 — Alertmanager ConfigMap (referenced by kube-prometheus-stack):**
- Name: `{{ include "euvoice-platform.fullname" . }}-alertmanager-config`
- Contains `alertmanager.yaml` key with:
  - `global.slack_api_url: "{{ .Values.monitoring.alertmanager.slackWebhookUrl }}"`
  - `route` with `receiver: slack-voiquyr`, `group_by: [alertname, severity]`, `group_wait`, `group_interval`, `repeat_interval` from values
  - `receivers` array with one entry `name: slack-voiquyr` using `slack_configs` with `channel`, `title: "[{{ .CommonLabels.severity | upper }}] {{ .CommonLabels.alertname }}"`, `text: "{{ range .Alerts }}{{ .Annotations.description }}{{ end }}"`

**Section 4 — Grafana Dashboard ConfigMap 1: Pipeline SLA:**
- Name: `{{ include "euvoice-platform.fullname" . }}-dashboard-pipeline-sla`
- Label: `{{ .Values.monitoring.grafana.sidecar.dashboards.label }}: "{{ .Values.monitoring.grafana.sidecar.dashboards.labelValue }}"`
- Data key: `voiquyr-pipeline-sla.json`
- Dashboard JSON includes panels for:
  - `histogram_quantile(0.50, ...)` p50 call latency
  - `histogram_quantile(0.95, ...)` p95 call latency (SLA line at 500ms)
  - `histogram_quantile(0.99, ...)` p99 call latency
  - Per-stage p95 latency (stt, llm, tts) as a single panel with 3 series
  - Flash mode hit rate: `rate(voiquyr_flash_mode_hits_total[5m]) / (rate(voiquyr_flash_mode_hits_total[5m]) + rate(voiquyr_flash_mode_misses_total[5m]))`
  - Error rate: `rate(voiquyr_call_latency_ms_count{status="error"}[5m])`
- Default time range: last 1 hour, auto-refresh: 30s
- The JSON can be a compact valid Grafana 9.x dashboard JSON structure

**Section 5 — Grafana Dashboard ConfigMap 2: Fallback and Health:**
- Name: `{{ include "euvoice-platform.fullname" . }}-dashboard-fallback-health`
- Same sidecar labels as above
- Data key: `voiquyr-fallback-health.json`
- Dashboard JSON includes panels for:
  - Circuit breaker state: `voiquyr_circuit_breaker_state` as stat panel with thresholds (0=green, 1=red, 2=yellow)
  - Fallback activations rate: `rate(voiquyr_fallback_activations_total[5m])`
  - vLLM vs Mistral API usage (if tracked — can show as placeholder using fallback counter)
  - Per-stage error rates over time (stt, llm, tts)
- Default time range: last 1 hour, auto-refresh: 30s

All 5 sections separated by `---` and each guarded by `{{- if .Values.monitoring.enabled }}` ... `{{- end }}`.
</action>
