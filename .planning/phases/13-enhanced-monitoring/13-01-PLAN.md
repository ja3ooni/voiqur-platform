# Plan 13-01: Prometheus Metrics Module

## Objective

Create `kiro/voiquyr/src/core/metrics.py` — a singleton module that defines all canonical Prometheus metrics for the Voiquyr pipeline. This is the foundation for all instrumentation in Plans 13-02 and 13-03.

## Tasks

### Task 1: Create metrics.py with singleton PrometheusMetrics

<read_first>
- `kiro/voiquyr/src/core/quality_monitor.py` — existing internal health/alert model; metrics.py supplements it with Prometheus counters, it does not replace it
- `kiro/voiquyr/src/core/__init__.py` — check what is exported from core, add metrics if appropriate
- `.planning/phases/13-enhanced-monitoring/13-CONTEXT.md` — canonical metric names, label constraints, histogram bucket choices (D-01 through D-04)
- `CLAUDE.md` — canonical metric name list: voiquyr_call_latency_ms, voiquyr_flash_mode_hit_rate, etc.
</read_first>

<action>
Create `kiro/voiquyr/src/core/metrics.py` with:

1. Import `prometheus_client` (Histogram, Gauge, Counter, REGISTRY).

2. Define LATENCY_BUCKETS = (10, 25, 50, 100, 250, 500, 1000, 2500) — millisecond buckets.

3. Define these metrics at module level inside a `PrometheusMetrics` dataclass (or plain module globals with a `get_metrics()` accessor that returns a namespace object):

   - `voiquyr_stt_latency_ms` — Histogram, labels=["status"], buckets=LATENCY_BUCKETS, description="STT stage latency in milliseconds"
   - `voiquyr_llm_latency_ms` — Histogram, labels=["status"], buckets=LATENCY_BUCKETS, description="LLM stage latency in milliseconds"
   - `voiquyr_tts_latency_ms` — Histogram, labels=["status"], buckets=LATENCY_BUCKETS, description="TTS stage latency in milliseconds"
   - `voiquyr_call_latency_ms` — Histogram, labels=["status"], buckets=LATENCY_BUCKETS, description="End-to-end call latency in milliseconds"
   - `voiquyr_flash_mode_hits_total` — Counter, labels=[], description="Flash mode speculative inference hits"
   - `voiquyr_flash_mode_misses_total` — Counter, labels=[], description="Flash mode speculative inference misses"
   - `voiquyr_fallback_activations_total` — Counter, labels=["provider"], description="LLM fallback activations by provider"
   - `voiquyr_circuit_breaker_state` — Gauge, labels=[], description="Circuit breaker state: 0=CLOSED, 1=OPEN, 2=HALF_OPEN"

4. Implement a `get_metrics()` function that returns the module-level metrics namespace (singleton pattern — safe to call multiple times).

5. Add a `record_stage_latency(stage: str, latency_ms: float, status: str = "ok")` helper that dispatches to the correct histogram by stage name ("stt", "llm", "tts", "call").

6. Add type annotations to all functions. Add module-level docstring explaining the metric names match CLAUDE.md canonical names.

Do NOT register any HTTP handler here — that is done in Plan 13-02 via prometheus-fastapi-instrumentator.
</action>

<acceptance_criteria>

- File contains `LATENCY_BUCKETS = (10, 25, 50, 100, 250, 500, 1000, 2500)`

- File contains `voiquyr_flash_mode_hits_total` and `voiquyr_flash_mode_misses_total` as Counter instances
- File contains `voiquyr_fallback_activations_total` as Counter with labels=["provider"]
