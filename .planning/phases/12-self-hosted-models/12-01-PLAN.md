# Phase 12 Plan: Self-Hosted Models

## Phase
12 - Self-Hosted Models

## Goal
vLLM deployment, OpenAI-compatible API, Voxtral STT fallback, model fallback chain

## Requirements
- SELF-01: vLLM server deployment for Mistral inference
- SELF-02: Self-hosted LLM API endpoint with OpenAI-compatible interface
- SELF-03: Voxtral STT integration (when released by Mistral)
- SELF-04: Model fallback chain: API → self-hosted

---

## Plan 12-01: vLLM Server Setup

### Objective
Set up vLLM server for self-hosted Mistral inference.

### Implementation
1. vLLM Docker container or bare metal setup
2. Model loading (Mistral 7B or larger)
3. GPU memory optimization
4. Health checks and metrics

### Files
- `deployments/vllm/Dockerfile`
- `deployments/vllm/docker-compose.yml`
- `deployments/vllm/config.yaml`

### Tests
- Server startup and health endpoint
- Model loading verification

---

## Plan 12-02: OpenAI-Compatible API

### Objective
Create OpenAI-compatible API endpoint for self-hosted models.

### Implementation
1. `/v1/completions` endpoint
2. `/v1/chat/completions` endpoint
3. Streaming with Server-Sent Events
4. Request/response format matching OpenAI API

### Files
- `src/agents/vllm_client.py` — vLLM API client
- `src/api/routers/vllm.py` — API endpoints

### Tests
- API compatibility tests
- Streaming response tests

---

## Plan 12-03: Model Fallback Chain

### Objective
Implement fallback chain: Mistral API → self-hosted vLLM → error.

### Implementation
1. Circuit breaker pattern for API failures
2. Automatic failover to vLLM
3. Health monitoring for each model
4. Fallback timeout handling (30s default)

### Files
- `src/agents/fallback_chain.py` — FallbackOrchestrator

### Tests
- Failover on API timeout
- Circuit breaker activation
